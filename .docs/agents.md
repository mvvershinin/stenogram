# Команда агентов

Спецификация: кто за что отвечает, кого звать под какую задачу, как устроены проверки.

Определения агентов — в `.claude/agents/`, вызывающие их команды — в `.claude/skills/`.

---

## Состав

Одиннадцать ролей: координатор, три технических эксперта по предметным областям,
три бизнес-роли и четыре роли контроля качества.

| # | Агент | Модель | Вид | Отвечает за |
|---|---|---|---|---|
| 00 | **coordinator** | sonnet | — | разбор задачи на фазы, выбор исполнителей, контрольные точки |
| 01 | **asr-expert** | opus | техн. | распознавание речи: whisper, параметры, качество текста |
| 02 | **diarization-expert** | opus | техн. | отпечатки, кластеризация, сглаживание, сшивка |
| 03 | **video-expert** | opus | техн. | детектор подсветки, плитки, работа с ffmpeg |
| 04 | **quality-analyst** | opus | бизн. | замеры без разметки, эксперименты, доказательства улучшений |
| 05 | **product-owner** | sonnet | бизн. | приоритеты дорожной карты, границы продукта, отказы от фич |
| 06 | **privacy-officer** | sonnet | бизн. | персональные данные, чистота репозитория перед публикацией |
| 07 | **architecture-validator** | sonnet | контроль | слои и направление зависимостей |
| 08 | **code-critic** | opus | контроль | состязательное ревью: баги, режимы отказа |
| 09 | **test-expert** | sonnet | контроль | pytest, синтетические фикстуры, покрытие |

Opus достаётся тем, чья работа требует рассуждения о неочевидном: три предметных
эксперта, аналитик качества и критик. Остальным хватает Sonnet.

## Команды

| Команда | Агент | Когда |
|---|---|---|
| `/orchestrate` | coordinator | задача трогает больше трёх файлов, новая фича, рефакторинг |
| `/develop-asr` | asr-expert | распознавание, модели whisper, качество текста |
| `/develop-diarization` | diarization-expert | разметка участников, кластеризация, сшивка |
| `/develop-video` | video-expert | детектор подсветки, плитки, ffmpeg |

## Обязательные проверки

**После любого изменения кода:**

```
/validate    → слои и зависимости не нарушены
/review      → баги и режимы отказа
```

**После любого изменения в разметке участников — дополнительно:**

```
/measure     → числа не просели
```

и **прочитать три минуты стенограммы глазами**. Это не формальность: вариант с дроблением
на окна прошёл по числам и был забракован именно чтением.

**Перед публикацией:**

```
/privacy-check → в репозитории нет записей, локальных путей и настоящих имён
```

## Схемы работы

### Актёр и критик

```
исполнитель (asr / diarization / video) пишет код
        ↓
code-critic ищет, чем это сломать
        ↓
нашёл → исполнитель правит → снова критик
не нашёл → готово
```

### Изменение в алгоритме разметки

Самый частый и самый опасный сценарий: здесь легко сделать хуже, не заметив.

```
1. quality-analyst  — зафиксировать числа ДО изменения
2. исполнитель      — внести изменение
3. quality-analyst  — замерить ПОСЛЕ, тем же протоколом
4. человек          — прочитать фрагмент стенограммы
5. code-critic      — ревью
```

Пропуск шага 1 обесценивает всё остальное: сравнивать будет не с чем.

### Новая фича

```
product-owner    — стоит ли делать, что именно и что не входит
coordinator      — фазы и исполнители
исполнители      — реализация
test-expert      — тесты
architecture-validator + code-critic — параллельно
```

### Подготовка к релизу

```
test-expert       — тесты проходят
packaging-expert  — сборка и вес
privacy-officer   — чистота репозитория
code-critic       — финальный проход
```

## Правила для всех агентов

**Читать перед работой.** [`domain.md`](domain.md) — термины, [`decisions/`](decisions/) —
почему сделано так. Половина «улучшений» отменяет решения, принятые по замерам.

**Не менять умолчания без замера.** `stay = 0.80`, `lag = 1.2`, порог надёжной реплики
1.5 с, `k` кластеров — за каждым числом стоит эксперимент. Меняете — приносите новый.

**Видео главнее звука.** Разметка по подсветке надёжнее отпечатков на порядок. Решение,
понижающее роль видео, требует записи в `decisions/`.

**Персональные данные не попадают в репозиторий** — ни в примеры, ни в фикстуры.

**Тяжёлые импорты — внутри функций.** `faster_whisper`, `sherpa_onnx`, `sklearn`
импортируются в теле функций, чтобы `--help` не ждал загрузки ONNX Runtime.

## Границы ответственности

Чтобы агенты не наступали друг другу на ноги:

| Спорная зона | Чья |
|---|---|
| `video.to_turns` — привязка границ к паузам | video-expert (границы), diarization-expert знает о контракте |
| `align.assign` — сшивка слов с участниками | diarization-expert |
| ffmpeg для звука | packaging-expert (бинарник), video-expert (параметры вызова) |
| Параметры whisper | asr-expert, но `word_timestamps` менять нельзя — см. [0005](decisions/0005-порядок-этапов.md) |
| Числа в документации | quality-analyst: он их мерил, он и правит |

# Рабочая база знаний

Здесь лежит то, что нужно агентам для работы: предметная область, протокол замеров,
регламент по данным, принятые решения, планы и спецификации.

Отличие от `docs/`: там **документация продукта** — её читает пользователь инструмента.
Здесь — **рабочие материалы разработки**, их читают агенты и разработчик.

## Что где

| Файл | Что внутри | Кто читает |
|---|---|---|
| [`agents.md`](agents.md) | Спецификация команды агентов: роли, модели, маршрутизация задач | координатор, все |
| [`domain.md`](domain.md) | Предметная область: плитка, реплика, отпечаток, подсветка | все |
| [`quality.md`](quality.md) | Протокол замеров качества без разметки, эталонные значения | quality-analyst |
| [`privacy.md`](privacy.md) | Обращение с записями и персональными данными | privacy-officer |
| [`decisions/`](decisions/) | Принятые архитектурные решения с обоснованием и замерами | все |
| [`plans/`](plans/) | Планы задач, датированные | координатор |
| [`specs/`](specs/) | Спецификации на конкретные работы | исполнители |

## Правила

**Решение с последствиями — в `decisions/`.** Если выбор между вариантами обосновывался
замерами, запись обязательна: иначе через полгода никто не вспомнит, почему модель
именно эта, и кто-нибудь «улучшит» обратно. Формат — короткий ADR: контекст, варианты,
решение, замеры, последствия.

**Замер без протокола — не замер.** Любое число в документации должно быть
воспроизводимо: что мерили, на чём, каким скриптом. Протокол — в [`quality.md`](quality.md).

**Персональные данные не попадают в репозиторий.** Ни в примеры документации, ни в
тесты, ни в фикстуры. Регламент — в [`privacy.md`](privacy.md).

**План устарел — не удаляем, помечаем.** В `plans/` видно, что и когда решалось.

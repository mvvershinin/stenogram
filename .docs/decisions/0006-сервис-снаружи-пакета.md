# 0006. Сервис — снаружи пакета

**Дата:** 2026-09-23 · **Статус:** принято

## Контекст

Стенограмма нужна асинхронным REST-декодером в будущем RAG-конвейере (текст, скан,
видеозапись → единый формат `Block[]`). Очередь, S3, HTTP — решение человека от
20.09.2026: не форк пайплайна, а тонкая обёртка сверху.

## Решение

`stenogram-service` — отдельный дистрибутив в `service/`, зависящий от `stenogram`
как от обычного пакета (`pip install . ./service`), а не наоборот.

- **S3/MinIO и HTTP не входят в `stenogram`.** Он остаётся офлайн-инструментом без
  сетевых зависимостей — решение [0004](0004-без-pytorch.md) о весе окружения касается
  и этого: `fastapi`/`uvicorn`/`minio` не должны тянуться тем, кому нужна только библиотека.
- **Порядок этапов — только в `pipeline.run`.** Сервис зовёт её как есть, не повторяя:
  один источник истины с CLI для [0005](0005-порядок-этапов.md).
- **Очередь — SQLite за интерфейсом `JobStore`, не redis.** Один GPU — один воркер,
  распределённая очередь решает проблему, которой нет; замена — другой класс за тем
  же интерфейсом.

## Последствия

- `stenogram` ставится и тестируется независимо; `service/pyproject.toml` берёт корень
  зависимостью, а не копирует код.
- Два изменения ушли в библиотеку, а не остались хаком сервиса: держатель модели
  whisper на процесс и `local_files_only`/`download_root` в `asr.load_model`.
- Сервис — Docker-образ с двумя командами (api/worker), модели — тома, не слои
  образа; см. `service/Dockerfile`, `service/docker-compose.yml`.

# Обращение с записями и персональными данными

Инструмент по своей природе работает с чувствительным материалом: совещания, переговоры,
заседания. В записи есть голоса, имена, должности, иногда коммерческая тайна и данные
третьих лиц, не дававших согласия ни на что.

Технически проект к этому готов — он работает офлайн и ничего не отправляет наружу.
Утечки случаются не через сеть, а через репозиторий, документацию и примеры.

---

## Правила

### 1. Записи не попадают в репозиторий

Ни исходные файлы, ни извлечённый звук, ни результаты. В `.gitignore` закрыты все
медиаформаты и выходные форматы. Проверять перед первым коммитом новой папки:

```bash
git ls-files | grep -iE "\.(mp4|mkv|avi|mov|webm|mp3|m4a|wav|ogg|flac|srt|vtt)$"
```

Пусто — хорошо.

### 2. Примеры в документации — вымышленные

Ни одной настоящей фамилии, названия организации, номера дела или договора. Даже если
запись ваша собственная: публичный репозиторий индексируется и форкается, откатить
публикацию нельзя.

Замеры при этом остаются настоящими — обезличивается **описание материала**, а не числа.
Так и написано в шапке `docs/алгоритмы.md`: диалоги вымышленные, числа реальные. Выдавать
придуманный диалог за реальный вывод — тоже нечестно, поэтому вымышленность указывается
явно.

### 3. Тестовые фикстуры — синтетические

Для тестов нужны короткие медиафайлы. Брать их из настоящих записей нельзя. Варианты:

- сгенерировать ffmpeg-ом: `testsrc` для видео, `sine` для звука;
- нарисовать плитки и рамку подсветки программно — детектору нужен цвет и мерцание,
  а не осмысленная картинка;
- записать несколько фраз голосом того, кто согласен.

### 4. Отчёты о проблемах — без содержимого записи

Если в проект добавляется сбор диагностики, в отчёт идут версии, параметры запуска и
трассировки. Расшифровка, имена участников и сам файл — никогда.

### 5. Кэш и временные файлы

Извлечённый WAV живёт во временной папке и удаляется по завершении. Флаг `--keep-wav`
оставляет его рядом с результатом — это осознанный выбор пользователя, но в документации
стоит помнить, что файл содержит всю запись целиком.

---

## Проверка перед публикацией

Прогонять перед каждым пушем в публичный репозиторий:

```bash
# 1. Медиа и результаты не отслеживаются
git ls-files | grep -iE "\.(mp4|m4a|wav|mp3|srt|vtt)$"

# 2. Локальные пути не утекли в документацию
grep -rn "/home/" --include="*.md" --include="*.py" . | grep -v "^\./\.git/"

# 3. Персональные данные в документации
grep -rniE "<список фамилий и организаций из вашего материала>" --include="*.md" .

# 4. Что реально уйдёт в коммит
git status --short && git ls-files | wc -l
```

Первые три должны быть пустыми.

Автоматизировано в навыке `/privacy-check`.

---

## Что делать, если данные уже попали в историю

Удаление файла новым коммитом **не помогает** — он остаётся в истории и доступен по
хешу. Нужен `git filter-repo` и принудительный пуш, а если репозиторий был публичным,
то ещё и допущение, что копию уже кто-то снял.

Поэтому проверка делается **до** первого пуша, а не после.

---

## Ответственность пользователя инструмента

Это стоит держать в голове при развитии продукта, особенно десктопного приложения:
запись совещания без ведома участников законна не везде и не всегда. Инструмент не
проверяет и не может проверять, было ли получено согласие. В интерфейсе десктопной
версии уместно об этом напомнить — один раз, без назидательности.

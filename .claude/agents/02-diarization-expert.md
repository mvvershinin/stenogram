Читай перед работой: `.docs/domain.md`, `.docs/quality.md`, все файлы
`.docs/decisions/`, `docs/алгоритмы.md` разделы 4–6.

## Роль

Отвечаешь за `stenogram/diarization.py` и `stenogram/align.py` — самую хрупкую часть
проекта. Здесь легко сделать хуже, не заметив этого.

## Главное правило

**Ни одно изменение не принимается без замера до и после.** Протокол — в
`.docs/quality.md`. Порядок:

1. зафиксировать числа на текущем коде;
2. внести изменение;
3. замерить тем же протоколом при том же `k`;
4. прочитать три минуты стенограммы глазами.

Шаг 4 обязателен. Вариант с дроблением реплик на окна проходил по числам и был забракован
именно чтением: монологи оказались изрублены в лапшу.

## Зона ответственности

| Функция | Что делает |
|---|---|
| `segment` | границы реплик через pyannote-segmentation-3.0 |
| `embed` | отпечатки CAM++, реплики короче 0.4 с пропускаются |
| `cluster` | k-means по надёжным репликам + HMM-сглаживание |
| `_viterbi` | декодирование с штрафом за смену говорящего |
| `estimate_speakers` | оценка числа участников по eigengap |
| `diarize` | путь только по звуку |
| `diarize_with_video` | гибридный путь: видео задаёт плитки, звук делит внутри |
| `align.assign` | сшивка слов с участниками, сборка реплик |

## Умолчания и их цена

| Параметр | Значение | Откуда |
|---|---|---|
| `stay` | 0.80 | замер: 194 смены при 85.4% согласованности |
| `scale` | 10.0 | подобрано вместе со `stay` |
| порог надёжной реплики | 1.5 с | короче — отпечаток шумит |
| `_MIN_EMBED_SEC` | 0.4 | ниже отпечаток бессмыслен |
| `_SEG_THRESHOLD` | 0.5 | намеренно низкий: реплики должны дробиться мелко |
| `max_pause` в сшивке | 3.0 (из CLI) | на записях совещаний паузы длиннее |

`_SEG_THRESHOLD` часто понимают неправильно: это порог **внутренней** кластеризации
sherpa, и он специально занижен, чтобы сегменты не слипались. Итоговые метки строятся
заново, поэтому «улучшать» его бессмысленно.

## Что уже проверено и не работает

Не предлагай это заново, не прочитав `.docs/decisions/0003-сглаживание-вместо-дробления.md`:

- **дробление реплик на окна по 2.5 с** — режет монологи, отпечаток окна слишком шумный;
- **кластеризация интервалов подсветки целиком** — 42–48%, люди в переговорной говорят
  по очереди без смены плитки;
- **ансамбль моделей отпечатков** — 80.3% против 83.0% у одной CAM++;
- **`stay = 0.92` глобально** — один участник забрал 44% времени.

## Предел метода

Косинус между центроидами двух заведомо разных групп участников на тестовой записи —
**0.958**. Отпечатки почти не различают людей: их забивают характеристики канала.
Потолок на записях из общей переговорной — около 85% на уровне реплики.

Это значит: задача «поднять качество разметки внутри плитки до 95%» в текущем классе
моделей нерешаема. Честный ответ — сказать об этом, а не изображать прогресс.

## Приоритет сигналов

Видео надёжнее звука на порядок. Изменение, понижающее роль видео в пользу отпечатков,
требует записи в `.docs/decisions/` и очень хороших замеров.

# Команда агентов проекта «Стенограмма»

Мульти-агентная разработка инструмента, превращающего запись видеоконференции
в стенограмму диалога с разбивкой по участникам.

**Стек:** Python 3.12 · faster-whisper (CTranslate2) · sherpa-onnx (ONNX Runtime) · numpy
**Полная спецификация:** [`.docs/agents.md`](../../.docs/agents.md)

---

## Обязательные правила

### 1. Сложные задачи — через координатора

Больше трёх файлов, новая фича, рефакторинг:

```
/orchestrate
```

### 2. После любого изменения кода

```
/validate     проверка слоёв и зависимостей
/review       баги и режимы отказа
```

### 3. Изменение в разметке участников — только с замером

```
/measure      ДО изменения — зафиксировать числа
   ...
/measure      ПОСЛЕ — тем же протоколом, при том же k
```

Плюс **прочитать три минуты стенограммы глазами**. Это не формальность: вариант
с дроблением реплик на окна прошёл по числам и был забракован именно чтением.

### 4. Перед публикацией

```
/privacy-check
```

## Архитектура проекта

Зависимости строго в одну сторону, циклов нет:

```
audio, models          нижний слой
video      → audio     только ради find_ffmpeg
asr                    автономен полностью
diarization → audio, models
align       → asr, diarization
render      → align
cli         → все
```

**Неочевидный порядок этапов:** распознавание речи идёт **до** разметки участников,
потому что границам подсветки нужны паузы между словами. См.
[решение 0005](../../.docs/decisions/0005-порядок-этапов.md).

**Два источника сигнала неравноценны:** видео (подсветка активного говорящего) размечает
плитки практически точно, звук (голосовые отпечатки) делит людей внутри плитки
приблизительно — около 85% на уровне реплики. Видео главнее.

## Схемы работы

### Актёр и критик

```
исполнитель пишет код → code-critic ищет, чем сломать
   → нашёл: исполнитель правит, снова критик
   → не нашёл: готово
```

### Изменение в алгоритме разметки

```
quality-analyst (замер ДО) → исполнитель → quality-analyst (замер ПОСЛЕ)
   → человек читает стенограмму → code-critic
```

Пропуск первого шага обесценивает всё остальное.

### Новая фича

```
product-owner → coordinator → исполнители → test-expert
   → architecture-validator + code-critic (параллельно)
```

# Проверка перед публикацией

## Действия

1. Прочитай `.docs/privacy.md`
2. Прогони проверки ниже
3. При находках запусти Agent (`model` sonnet, правила из
   `.claude/agents/06-privacy-officer.md`) для разбора и исправления

## Проверки

```bash
# 1. Медиа и результаты не отслеживаются git
git ls-files | grep -iE "\.(mp4|mkv|avi|mov|webm|mp3|m4a|wav|ogg|flac|srt|vtt)$"

# 2. Локальные пути не утекли
grep -rn "/home/\|/Users/\|C:\\\\Users" --include="*.md" --include="*.py" --include="*.sh" . \
  | grep -v "^\./\.git/"

# 3. Вес индекса — резкий рост означает лишнее в коммите
git ls-files -z | xargs -0 du -ch | tail -1

# 4. Что уйдёт в коммит
git status --short
```

Первые две проверки должны быть пустыми.

## Настоящие имена

Автоматически не ищутся — список зависит от материала, на котором работали. Спроси
пользователя, какие фамилии и организации могли попасть в примеры, и поищи их.

Реальный случай из истории проекта: в документацию попал фрагмент настоящего заседания
с фамилиями участников, заметили только перед публикацией.

## Если данные уже в истории

Удаление новым коммитом не помогает — файл остаётся доступен по хешу. Нужен
`git filter-repo` и принудительный пуш, а для публичного репозитория надо исходить
из того, что копию уже сняли. Поэтому проверка делается ДО пуша.

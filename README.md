# Стенограмма

Превращает запись видеоконференции или совещания в стенограмму диалога: распознаёт речь
и размечает, кто что говорит.

Работает офлайн на CPU. Ни API-ключей, ни аккаунтов, ни облачных сервисов — запись
никуда не отправляется.

```
$ ./stenogram.sh совещание.mp4 --speakers 4 --names "Иванов,Петров,Сидорова"

[1/4] Извлекаю аудио из совещание.mp4 ...
      42.7 мин звука
[2/4] Ищу подсветку активного говорящего в видео ...
      плиток найдено: 4
[3/4] Распознаю речь ...
      язык: ru (уверенность 100%), длительность 42.7 мин
[4/4] Определяю участников ...
      участников: 4, реплик: 618
Собираю стенограмму ...

Готово за 24.8 мин:
  Иванов             15.2 мин  36%  реплик:  201  слов: 2604
  Петров             12.9 мин  30%  реплик:  178  слов: 2210
  Сидорова            9.4 мин  22%  реплик:  152  слов: 1588
  Говорящий 4         5.2 мин  12%  реплик:   87  слов:  902

  → совещание.txt
  → совещание.md
  → совещание.srt
  → совещание.json
```

## Чем отличается

Обычная диаризация опирается только на голосовые отпечатки и разваливается там, где
запись сделана из общей переговорной: эхо, один микрофон на всех, похожие голоса.

Здесь основной признак — **подсветка активного говорящего в самом видео**. Zoom, Teams,
TrueConf, Telemost и корпоративные системы ВКС обводят рамкой плитку того, кто сейчас
говорит. Этот сигнал точнее любого голосового отпечатка: на часовой записи созвона он дал
разметку без единого пропуска, тогда как отпечатки на том же материале путались.

Плитки участников находятся автоматически, настраивать раскладку не нужно. Голосовые
отпечатки остаются как второй эшелон — они делят людей внутри одной плитки, когда
несколько человек сидят перед общей камерой.

Подробности: [алгоритмы](docs/алгоритмы.md).

## Ограничения

Осознанные границы, а не временные недоделки:

- **Одновременная речь не поддерживается.** Перекрывающаяся речь достаётся кому-то
  одному: разметка одноголосая по построению.
- **Имена участников с экрана не читаются.** Подписи под плитками не распознаются.
  Участники выдаются как «Говорящий 1..N» в порядке номеров, имена задаются вручную
  через `--names`.
- **Людей за одной камерой видео не разделяет.** Кто именно из сидящих в переговорной
  говорит — по картинке не определить. Там работают голосовые отпечатки, и только
  приблизительно: насколько — в разделе
  [«Точность разбивки по участникам»](#точность-разбивки-по-участникам).
- **Перевода и пересказа нет.** На выходе стенограмма, а не изложение.

## Установка

```bash
./setup.sh
```

Создаёт `./venv`, ставит зависимости и скачивает модели диаризации. Модель распознавания
речи скачается при первом запуске. Всего ~2.7 ГБ, один раз — дальше интернет не нужен.

Нужен `ffmpeg`: берётся системный, а если его нет — подтягивается пакетом `static-ffmpeg`
в то же окружение, без прав root.

Требования: Python 3.10+, ~3 ГБ на диске, 4 ГБ ОЗУ. Видеокарта не нужна, но с NVIDIA
всё считается в 10–20 раз быстрее.

Linux и macOS — напрямую. На Windows скрипты запускаются из WSL:
нативного bash в системе нет, `./setup.sh` без него не стартует.

## Запуск

Минимально нужное — путь к файлу:

```bash
/путь/к/проекту/stenogram.sh /путь/к/вашему/видео.mp4
```

Запускать можно из любой папки, переходить в проект не нужно. Результаты — `видео.txt`,
`.md`, `.srt`, `.json` — появятся рядом с исходным файлом. Модели скачиваются один раз,
при повторных запусках сразу идёт работа.

Форматы на входе — любые, которые понимает ffmpeg: mp4, mkv, avi, mp3, wav, m4a, ogg.
Аудиофайлы обрабатываются так же, просто без шага с подсветкой.

### Типовые запуски

```bash
# всё по умолчанию: число участников оценивается само
./stenogram.sh совещание.mp4

# знаете число участников — укажите, это главный рычаг качества
./stenogram.sh созвон.mp4 --speakers 5

# часть людей в переговорной перед общей камерой: трое в комнате, один удалённо
./stenogram.sh дейли.mp4 --tile-speakers "3,1"

# подписать участников (порядок — по номерам из сводки прошлого прогона)
./stenogram.sh дейли.mp4 --names "Аня,Борис,Вика,Глеб"

# подсказать тему и фамилии — заметно улучшает имена собственные
./stenogram.sh дейли.mp4 --prompt "Дейли команды. Имена: Аня, Борис, Вика. Термины: деплой, миграция"

# выбрать форматы и сложить в отдельную папку
./stenogram.sh подкаст.mp3 -f txt,srt -o ./результаты

# только текст, без разбивки по участникам
./stenogram.sh лекция.wav --no-diarization

# быстрый черновик: впятеро быстрее, но хуже на терминах и фамилиях
./stenogram.sh совещание.mp4 -m small
```

### Сколько человек указывать

Число плиток проект определяет сам и печатает на втором шаге. Поэтому удобно запустить
сначала без флагов, посмотреть на вывод и при необходимости уточнить:

```
[2/4] Ищу подсветку активного говорящего в видео ...
      плиток найдено: 2
```

Дальше зависит от того, как рассажены люди:

- **каждый со своего устройства** — плиток столько же, сколько людей, уточнять нечего;
- **несколько человек перед общей камерой** — плиток меньше, чем людей. Тогда
  `--tile-speakers "3,1"`: по одному числу на каждую **найденную** плитку, слева направо;
- **число плиток неизвестно, а число людей известно** — `--speakers N`, лишние люди
  отойдут к самой говорливой плитке.

Чисел в `--tile-speakers` должно быть ровно столько, сколько плиток напечатал шаг `[2/4]`.
Молчаливую плитку пропускать нельзя: если кто-то за весь разговор ни разу не заговорил,
его плитка всё равно занимает своё число (любое, оно не будет использовано) — иначе
следующие числа сдвинутся на чужие плитки. Расхождение заметно на шаге `[4/4]`: там
печатаются номера плиток, за которыми нашлась речь, и их бывает меньше, чем найдено.

### Ключевые параметры

| Параметр | Зачем |
|---|---|
| `--speakers N` | Точное число участников. **Самый сильный рычаг качества** — если знаете, укажите |
| `--tile-speakers "3,1"` | Сколько человек за каждой найденной плиткой видео, слева направо. Точнее, чем `--speakers` |
| `--names "А,Б,В"` | Имена вместо «Говорящий 1». Порядок — по номерам участников, а не по времени речи. Точечно: `"3=Глеб"` |
| `--model` | `large-v3-turbo` (по умолчанию), `large-v3` точнее и втрое медленнее, `small` для черновика |
| `--language ru` | Отключает автоопределение языка |
| `--prompt "..."` | Тема, термины, фамилии — заметно улучшает распознавание имён собственных |
| `--no-video` | Не использовать подсветку, только голос |
| `--highlight-lag` | На сколько секунд подсветка отстаёт от речи (по умолчанию 1.2) |
| `--denoise` | Шумодав и выравнивание громкости. Помогает на плохих записях, на чистых мешает |
| `--threads N` | Потоки CPU (по умолчанию — все, кроме двух) |
| `--device cuda --compute-type float16` | Считать на видеокарте NVIDIA |

Полный список — `./stenogram.sh --help` и [справочник параметров](docs/эксплуатация.md).

### Чтобы вызывать короче

```bash
echo "alias стенограмма='/путь/к/проекту/stenogram.sh'" >> ~/.zshrc
source ~/.zshrc
```

Дальше просто `стенограмма видео.mp4`.

### Сколько ждать

Ориентир для 12 ядер CPU без видеокарты — **около 35 минут на час записи**. Три четверти
этого времени занимает распознавание речи. Ускорение: `--model small` (впятеро быстрее,
заметно хуже) или видеокарта NVIDIA — `--device cuda --compute-type float16` даёт час
записи за 2–3 минуты. Подробная разбивка по этапам — в [эксплуатации](docs/эксплуатация.md).

### Если что-то пошло не так

Отказы печатаются одной строкой: `Ошибка: ...`, код возврата 1. Для баг-репорта этого
мало — повторите команду с переменной окружения, и вместо строки будет полный трейсбек:

```bash
STENOGRAM_TRACEBACK=1 ./stenogram.sh запись.mp4
```

Ctrl+C остаётся Ctrl+C (код 130), а `... | head` — штатным завершением (код 0).
Частые случаи и их разбор — в [эксплуатации](docs/эксплуатация.md).

**Текста заметно меньше, чем речи в записи.** На шумной записи, например из зала суда,
детектор речи принимает её за шум и выбрасывает до распознавания. Ошибки при этом нет,
текст просто обрывается кусками. Помогает `--denoise`: на записи 102 минуты он дал 7464 слова
вместо 2231.

## Сервис на машине с видеокартой

Если карта стоит на другом компьютере, запись можно отправлять туда одной командой.
На машине с картой работает REST-сервис в Docker, он поднимается сам при её включении.
Стенограмма возвращается и ложится рядом с записью:

```bash
service/transcribe.sh запись.mp4

# шумная запись: второй аргумент — параметры задачи
service/transcribe.sh запись.mp3 '{"language": "ru", "denoise": true}'
```

Запись 102 минуты считается 6–9 минут. Результат: `запись.txt` и `запись.blocks.json`.
Запись при этом уходит на эту машину и остаётся в её хранилище, так что офлайн здесь
значит «внутри своей сети». Развёртывание, REST API и коды ошибок — в
[документации сервиса](service/README.md).

## Форматы вывода

| Формат | Что внутри |
|---|---|
| `txt` | Диалог с таймкодами: `[00:12:34] Говорящий 2: текст` |
| `md` | То же плюс таблица участников со статистикой |
| `srt` / `vtt` | Субтитры с именем говорящего в реплике |
| `json` | Полные данные: реплики, потайминговка по каждому слову, статистика |

## Как это работает

```
медиафайл
   │
   ├─ ffmpeg ─────────► WAV 16 кГц моно ─────► РАСПОЗНАВАНИЕ (faster-whisper)
   │                                              → текст + время каждого слова
   │                                                        │
   ├─ ffmpeg ─────────► полоски краёв плиток                │
   │                        │                               │
   │                   ПОДСВЕТКА АКТИВНОГО ГОВОРЯЩЕГО       │
   │                   → кто говорит, с точностью 0.2 с     │
   │                        │                               │
   │                        ├──── границы притягиваются ────┤
   │                        │      к паузам между словами   │
   │                        ▼                               │
   │                   ГОЛОСОВЫЕ ОТПЕЧАТКИ                  │
   │                   делят людей внутри одной плитки      │
   │                        │                               │
   │                        └────────► СШИВКА ◄─────────────┘
   │                              слово → участник
   ▼
txt / md / srt / vtt / json
```

Два независимых прохода: один слышит **что** сказано, другой — **кем**. Сшиваются по
времени: каждое слово достаётся тому участнику, чей интервал речи перекрывает его сильнее.

Подробно: [архитектура](docs/архитектура.md) · [алгоритмы](docs/алгоритмы.md).

## Точность разбивки по участникам

Разметка по видео и разметка по голосу — принципиально разного качества, и это стоит
учитывать при чтении результата.

**По видео — надёжно.** Кто из плиток говорит, определяется практически точно. Ошибки
остаются на быстрых перебиваниях: когда реплики короче секунды, подсветка не успевает
переключиться и обмен репликами склеивается в одну.

**По голосу — приблизительно.** Разделение людей внутри одной плитки держится на
голосовых отпечатках. На записи из общей переговорной проверка даёт около 85%
совпадения на уровне реплики: длинный монолог может разъехаться на двух «участников»,
а похожие голоса — слиться в одного. Это оценка, а не факт.

Что помогает: точное число участников (`--speakers`, ещё лучше `--tile-speakers`),
раздельные микрофоны, длинные реплики.

Что ломает: общая камера и общий микрофон на несколько человек, перебивания и речь
поверх речи, плохая связь и эхо.

Имена участников из видео не читаются: они выдаются как «Говорящий 1..N», сопоставить
с людьми — через `--names`.

**Нумерация идёт не по времени речи.** Номер участника берётся от порядка плиток в кадре,
а внутри плитки — от номера кластера голосов. Сводка в конце прогона отсортирована по
убыванию времени, но номера в ней настоящие: «Говорящий 3» останется третьим, даже если
говорил больше всех. Поэтому надёжный способ подписать участников — прогнать один раз без
`--names`, прочитать сводку и подставить имена по номерам, а точечная форма `"3=Глеб"`
безопаснее позиционной.

## Структура

```
stenogram/
  audio.py         извлечение и загрузка звука (ffmpeg)
  video.py         поиск плиток и подсветки активного говорящего
  models.py        скачивание и кэш ONNX-моделей
  diarization.py   сегментация, голосовые отпечатки, кластеризация
  asr.py           распознавание речи (faster-whisper)
  align.py         сшивка текста с участниками, сборка реплик
  render.py        txt / md / srt / vtt / json
  cli.py           разбор аргументов и оркестрация
service/           REST-сервис: очередь, S3, Docker, клиент transcribe.sh
docs/              техдокументация и план развития
setup.sh           разворачивает окружение
stenogram.sh       запуск из локального venv
```

Модули самостоятельны — пайплайн собирается и из кода:

```python
from pathlib import Path
from stenogram import align, asr, audio, diarization, render, video

src = Path("запись.mp4")
wav = audio.extract_wav(src, Path("/tmp/a.wav"))
segments, lang = asr.transcribe(wav, language="ru")

tiles = video.find_tiles(src)                       # плитки участников
labels, step = video.active_speaker(src, tiles)     # кто подсвечен в каждый момент
vturns = video.to_turns(labels, step, video.word_gaps(segments))

# числа — по плиткам из find_tiles, слева направо: семеро в переговорной, один удалённо
turns, _ = diarization.diarize_with_video(audio.load_wav(wav), vturns, tile_speakers=[7, 1])
render.write(align.assign(segments, turns), Path("запись"), ["txt", "json"])
```

## Зависимости и лицензии

| Компонент | Роль | Лицензия |
|---|---|---|
| faster-whisper + CTranslate2 | распознавание речи | MIT |
| sherpa-onnx + ONNX Runtime | запуск моделей диаризации | Apache 2.0 / MIT |
| pyannote-segmentation-3.0 | границы реплик | MIT (сборка ONNX от k2-fsa) |
| WeSpeaker CAM++ (VoxCeleb) | голосовые отпечатки | Apache 2.0 |
| scikit-learn, numpy | кластеризация и вычисления | BSD |
| ffmpeg | извлечение звука и кадров | LGPL/GPL |

PyTorch не нужен — всё работает на ONNX Runtime и CTranslate2. Это экономит ~2.5 ГБ и
убирает самый капризный шаг установки. Gated-моделей (требующих токен Hugging Face и
принятия условий) в сборке нет.

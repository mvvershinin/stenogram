# Стенограмма

Превращает запись разговора в текст с таймкодами и разбивкой по участникам. Работает и с
видео, и с обычным аудио: созвон из Zoom или Teams, совещание, судебное заседание,
интервью, подкаст, лекция.

На выходе получается такой текст:

```
[00:12:34] Иванов: Давайте начнём с бюджета.
[00:12:41] Петров: Там нужно уточнить две статьи.
[00:12:47] Иванов: Хорошо, какие именно?
```

## Что можно расшифровать

Команда одна и та же, тип файла программа определяет сама.

| Запись | Форматы | Как определяется, кто говорит |
|---|---|---|
| **Только звук** | mp3, wav, m4a, ogg и другие | По голосу. Работает приблизительно: похожие голоса могут слиться, а один человек разделиться на двух |
| **Видео созвона** | mp4, mkv, avi и другие | По рамке вокруг того, кто говорит. Почти без ошибок, а голос нужен, только если несколько человек сидят перед одной камерой |

Текст распознаётся одинаково в обоих случаях. Разница только в разбивке по участникам. Подробнее — в разделе [«Точность разбивки»](#точность-разбивки-по-участникам).

## Где считать

| Вариант | Час записи | Что нужно |
|---|---|---|
| **На своём компьютере** | около 35 минут на 12 ядрах | Python 3.10+, 3 ГБ на диске, 4 ГБ памяти |
| **На своей видеокарте NVIDIA** | распознавание 1.5 минуты, разделение на участников ещё около 5 | то же плюс драйвер NVIDIA и 1.4 ГБ библиотек, [инструкция](#видеокарта-nvidia) |
| **На отдельной машине с видеокартой** | то же, запись отправляется туда одной командой | Docker на этой машине, [инструкция](#сервис-на-машине-с-видеокартой) |

На своём компьютере всё работает офлайн: без ключей и аккаунтов, запись никуда не
отправляется. Интернет нужен один раз, чтобы скачать модели. В варианте с отдельной
машиной запись уходит на неё и хранится в S3-хранилище сервиса, своём или внешнем.

## Как начать

### 1. Установить

```bash
git clone https://github.com/mvvershinin/stenogram.git
cd stenogram
./setup.sh
```

Linux и macOS работают напрямую, на Windows запускайте из WSL. `ffmpeg` ставить не нужно:
если его нет в системе, программа подтянет свой. Модель распознавания скачается при первом
запуске, всего уйдёт около 2.7 ГБ.

### 2. Расшифровать запись

Передайте путь к файлу. Запускать можно из любой папки:

```bash
# аудио
/путь/к/проекту/stenogram.sh /путь/к/разговор.mp3

# видео
/путь/к/проекту/stenogram.sh /путь/к/созвон.mp4
```

В терминале видно, как идёт работа. Для аудио строка «Подсветка не найдена» — это норма:
видео нет, поэтому участники определяются по голосу.

```
[1/4] Извлекаю аудио из разговор.mp3 ...
      42.7 мин звука
[2/4] Подсветка не найдена — участники только по голосу
[3/4] Распознаю речь ...
[4/4] Определяю участников ...
Собираю стенограмму ...
```

Когда программа закончит, рядом с записью появятся файлы с тем же именем: `разговор.txt`
с текстом, а также `.md`, `.srt` и `.json`. [Что в них](#форматы-вывода).

### 3. Улучшить результат

Участники сначала называются «Говорящий 1», «Говорящий 2» и так далее. Что можно добавить
к команде:

```bash
# Лучшее, что можно сделать: сказать, сколько людей в записи
./stenogram.sh интервью.mp3 --speakers 2

# Подставить имена: номера видны в сводке в конце первого запуска
./stenogram.sh интервью.mp3 --speakers 2 --names "1=Анна,2=Борис"

# Запись шумная: зал суда, переговорная, плохой микрофон.
# Если текста намного меньше, чем речи, начинайте с этого
./stenogram.sh заседание.mp3 --language ru --denoise

# Подсказать тему и фамилии, чтобы модель их не перевирала
./stenogram.sh заседание.mp3 --prompt "Судебное заседание. Фамилии: Иванов, Петрова"

# Нужен только текст, без участников
./stenogram.sh лекция.wav --no-diarization

# Быстрый черновик: впятеро быстрее, но хуже на терминах и фамилиях
./stenogram.sh разговор.mp3 -m small

# Выбрать форматы и папку для результата
./stenogram.sh подкаст.mp3 -f txt,srt -o ./результаты
```

Только для видео: если несколько человек сидят перед одной камерой, укажите, сколько людей
за каждой плиткой созвона. Например, трое в комнате и один удалённо:

```bash
./stenogram.sh дейли.mp4 --tile-speakers "3,1"
```

### Видеокарта NVIDIA

На карте распознавание идёт примерно в 20 раз быстрее. Работает и с аудио, и с видео. Нужен
драйвер NVIDIA. `./setup.sh` библиотеки для карты не ставит, это отдельный шаг на 1.4 ГБ:

```bash
./setup.sh
./venv/bin/pip install "nvidia-cublas-cu12>=12,<13" "nvidia-cudnn-cu12>=9,<10"
```

Перед запуском укажите путь к библиотекам. Это нужно в каждом новом терминале, а `python3.12`
замените на свою версию:

```bash
N="$PWD/venv/lib/python3.12/site-packages/nvidia"
export LD_LIBRARY_PATH="$N/cublas/lib:$N/cudnn/lib"

./stenogram.sh запись.mp3 --device cuda --compute-type float16
```

Если путь не указан, программа запустится, увидит карту и упадёт уже на распознавании.
Разделение на участников всегда идёт на процессоре.

## Настройка запуска

### Сколько человек указывать в видео

Для аудио всё просто: `--speakers N`. Для видео число плиток проект определяет сам и печатает на втором шаге. Поэтому удобно запустить
сначала без флагов, посмотреть на вывод и при необходимости уточнить:

```
[2/4] Ищу подсветку активного говорящего в видео ...
      плиток найдено: 2
```

Дальше зависит от того, как рассажены люди:

- **каждый со своего устройства** — плиток столько же, сколько людей, уточнять нечего;
- **несколько человек перед общей камерой** — плиток меньше, чем людей. Тогда
  `--tile-speakers "3,1"`: по одному числу на каждую **найденную** плитку, слева направо;
- **число плиток неизвестно, а число людей известно** — `--speakers N`, лишние люди
  отойдут к самой говорливой плитке.

Чисел в `--tile-speakers` должно быть ровно столько, сколько плиток напечатал шаг `[2/4]`.
Молчаливую плитку пропускать нельзя: если кто-то за весь разговор ни разу не заговорил,
его плитка всё равно занимает своё число (любое, оно не будет использовано) — иначе
следующие числа сдвинутся на чужие плитки. Расхождение заметно на шаге `[4/4]`: там
печатаются номера плиток, за которыми нашлась речь, и их бывает меньше, чем найдено.

### Ключевые параметры

| Параметр | Зачем |
|---|---|
| `--speakers N` | Точное число участников. **Самый сильный рычаг качества** — если знаете, укажите |
| `--tile-speakers "3,1"` | Сколько человек за каждой найденной плиткой видео, слева направо. Точнее, чем `--speakers` |
| `--names "А,Б,В"` | Имена вместо «Говорящий 1». Порядок — по номерам участников, а не по времени речи. Точечно: `"3=Глеб"` |
| `--model` | `large-v3-turbo` (по умолчанию), `large-v3` точнее и втрое медленнее, `small` для черновика |
| `--language ru` | Отключает автоопределение языка |
| `--prompt "..."` | Тема, термины, фамилии — заметно улучшает распознавание имён собственных |
| `--no-video` | Не использовать подсветку, только голос |
| `--highlight-lag` | На сколько секунд подсветка отстаёт от речи (по умолчанию 1.2) |
| `--denoise` | Шумодав и выравнивание громкости. Помогает на плохих записях, на чистых мешает |
| `--threads N` | Потоки CPU (по умолчанию — все, кроме двух) |
| `--device cuda --compute-type float16` | Считать на видеокарте NVIDIA |

Полный список — `./stenogram.sh --help` и [справочник параметров](docs/эксплуатация.md).

### Чтобы вызывать короче

```bash
echo "alias стенограмма='/путь/к/проекту/stenogram.sh'" >> ~/.zshrc
source ~/.zshrc
```

Дальше просто `стенограмма видео.mp4`.

### Сколько ждать

Ориентир для 12 ядер CPU без видеокарты — **около 35 минут на час записи**. Три четверти
этого времени занимает распознавание речи. Ускорение: `--model small` (впятеро быстрее,
заметно хуже) или [видеокарта NVIDIA](#видеокарта-nvidia) — `--device cuda --compute-type float16`
распознаёт час записи за 1.5 минуты. Подробная разбивка по этапам — в [эксплуатации](docs/эксплуатация.md).

### Если что-то пошло не так

Отказы печатаются одной строкой: `Ошибка: ...`, код возврата 1. Для баг-репорта этого
мало — повторите команду с переменной окружения, и вместо строки будет полный трейсбек:

```bash
STENOGRAM_TRACEBACK=1 ./stenogram.sh запись.mp4
```

Ctrl+C остаётся Ctrl+C (код 130), а `... | head` — штатным завершением (код 0).
Частые случаи и их разбор — в [эксплуатации](docs/эксплуатация.md).

**Результат обрезал имя файла.** Если в имени записи есть точки, например `суд.20.10.2026.mp3`,
результат получит имя `суд.20.10.txt`, и две записи за один день затрут друг друга. Перед
запуском замените точки в имени на другой символ.

**Текста заметно меньше, чем речи в записи.** На шумной записи, например из зала суда,
детектор речи принимает её за шум и выбрасывает до распознавания. Ошибки при этом нет,
текст просто обрывается кусками. Помогает `--denoise`: на записи 102 минуты он дал 7464 слова
вместо 2231.

## Сервис на машине с видеокартой

Если карта стоит на другом компьютере, запись отправляется туда одной командой, а
стенограмма возвращается и ложится рядом с записью. На машине с картой работает REST-сервис
в Docker, он поднимается сам при её включении. Запись 102 минуты считается 6–9 минут.

Запись уходит в S3-хранилище сервиса и остаётся там. С локальным MinIO это значит «внутри
своей сети», с облачным S3 запись покидает её. API открыт всей локальной сети без авторизации.

### Сборка и запуск на машине с картой

**1. Поставить Docker и доступ к карте из контейнеров.** Нужны драйвер NVIDIA,
[Docker Engine](https://docs.docker.com/engine/install/) и
[NVIDIA Container Toolkit](https://docs.nvidia.com/datacenter/cloud-native/container-toolkit/latest/install-guide.html).
Проверка: команда должна показать вашу карту.

```bash
sudo docker run --rm --gpus all ubuntu:24.04 nvidia-smi -L
```

**2. Скачать проект и модели.** Модели в образ не входят, контейнеры берут их с диска:

```bash
git clone https://github.com/mvvershinin/stenogram.git
cd stenogram
./setup.sh
./venv/bin/python -m stenogram.models --fetch --whisper large-v3-turbo
```

**3. Настроить.** В `service/.env` пропишите пароль хранилища и абсолютные пути к моделям:

```bash
cd service
cp .env.example .env
```

```bash
STENOGRAM_S3_SECRET_KEY=придумайте-пароль-от-8-символов
STENOGRAM_MODELS_DIR=/home/вы/.cache/stenogram
STENOGRAM_WHISPER_MODELS_DIR=/home/вы/.cache/huggingface/hub
```

И добавьте туда же две строки: сервис на карте и все ядра на разметку участников (укажите
удвоенное число ядер):

```bash
COMPOSE_PROFILES=gpu
STENOGRAM_THREADS=12
```

**4. Выбрать хранилище.** Записи и результаты лежат в S3. Подходит **любое S3-совместимое
хранилище**: своё или облачное, MinIO в комплекте не обязателен.

*Своё S3.* MinIO не запускается и не нужен. Бакет создайте заранее, а в `.env` замените
блок хранилища:

```bash
COMPOSE_FILE=docker-compose.yml
STENOGRAM_S3_ENDPOINT=s3.example.com
STENOGRAM_S3_SECURE=true
STENOGRAM_S3_REGION=us-east-1
STENOGRAM_S3_ACCESS_KEY=ваш-ключ
STENOGRAM_S3_SECRET_KEY=ваш-секрет
```

*Локальный MinIO.* Он живёт в отдельном файле `docker-compose.minio.yml` и включён в
`.env.example`. Чтобы заливать записи с другого компьютера, задайте:

```bash
COMPOSE_FILE=docker-compose.yml:docker-compose.minio.yml:docker-compose.lan.yml
```

Образы MinIO больше не скачиваются с `quay.io` и Docker Hub (проверено 06.11.2026). Если
они есть на другой машине, перенесите их до следующего шага:

```bash
docker save quay.io/minio/minio:RELEASE.2025-04-08T15-41-24Z \
    quay.io/minio/mc:RELEASE.2025-04-08T15-39-49Z | ssh адрес-машины sudo docker load
```

**5. Собрать и запустить.** Первая сборка занимает около 20 минут и скачивает 1.4 ГБ
библиотек CUDA, следующие — несколько минут. Не добавляйте `--no-cache`: с ним всё
скачивается заново.

```bash
sudo docker compose up -d --build
curl localhost:8000/healthz    # {"status":"ok"}
```

Запускать сервис заново после включения машины не нужно, это делает Docker.

### Запуск расшифровки со своего компьютера

Нужны `curl`, `jq` и клон этого репозитория. Один раз положите адреса и ключи в
`~/.config/stenogram/remote.env`:

```bash
STENOGRAM_API=http://адрес-машины:8000
STENOGRAM_S3_URL=http://адрес-машины:9000
STENOGRAM_S3_ACCESS_KEY=stenogram
STENOGRAM_S3_SECRET_KEY=тот-же-пароль
```

Для своего S3 укажите его адрес и ключи, а также `STENOGRAM_S3_BUCKET` и
`STENOGRAM_S3_REGION`, если они отличаются от `stenogram` и `us-east-1`.

Дальше одна команда на запись:

```bash
service/transcribe.sh запись.mp4

# шумная запись: второй аргумент — параметры задачи
service/transcribe.sh запись.mp3 '{"language": "ru", "denoise": true}'
```

Ход работы печатается в терминале. Результат — `запись.txt` и `запись.blocks.json` рядом
с записью. REST API и коды ошибок описаны в [документации сервиса](service/README.md).

## Форматы вывода

| Формат | Что внутри |
|---|---|
| `txt` | Диалог с таймкодами: `[00:12:34] Говорящий 2: текст` |
| `md` | То же плюс таблица участников со статистикой |
| `srt` / `vtt` | Субтитры с именем говорящего в реплике |
| `json` | Полные данные: реплики, потайминговка по каждому слову, статистика |

## Чем отличается от обычной диаризации

Обычная диаризация опирается только на голосовые отпечатки и разваливается там, где
запись сделана из общей переговорной: эхо, один микрофон на всех, похожие голоса.

Здесь основной признак — **подсветка активного говорящего в самом видео**. Zoom, Teams,
TrueConf, Telemost и корпоративные системы ВКС обводят рамкой плитку того, кто сейчас
говорит. Этот сигнал точнее любого голосового отпечатка: на часовой записи созвона он дал
разметку без единого пропуска, тогда как отпечатки на том же материале путались.

Плитки участников находятся автоматически, настраивать раскладку не нужно. Голосовые
отпечатки остаются как второй эшелон — они делят людей внутри одной плитки, когда
несколько человек сидят перед общей камерой.

Подробности: [алгоритмы](docs/алгоритмы.md).

## Ограничения

Осознанные границы, а не временные недоделки:

- **Одновременная речь не поддерживается.** Перекрывающаяся речь достаётся кому-то
  одному: разметка одноголосая по построению.
- **Имена участников с экрана не читаются.** Подписи под плитками не распознаются.
  Участники выдаются как «Говорящий 1..N» в порядке номеров, имена задаются вручную
  через `--names`.
- **Людей за одной камерой видео не разделяет.** Кто именно из сидящих в переговорной
  говорит — по картинке не определить. Там работают голосовые отпечатки, и только
  приблизительно: насколько — в разделе
  [«Точность разбивки по участникам»](#точность-разбивки-по-участникам).
- **Перевода и пересказа нет.** На выходе стенограмма, а не изложение.

## Как это работает

```
медиафайл
   │
   ├─ ffmpeg ─────────► WAV 16 кГц моно ─────► РАСПОЗНАВАНИЕ (faster-whisper)
   │                                              → текст + время каждого слова
   │                                                        │
   ├─ ffmpeg ─────────► полоски краёв плиток                │
   │                        │                               │
   │                   ПОДСВЕТКА АКТИВНОГО ГОВОРЯЩЕГО       │
   │                   → кто говорит, с точностью 0.2 с     │
   │                        │                               │
   │                        ├──── границы притягиваются ────┤
   │                        │      к паузам между словами   │
   │                        ▼                               │
   │                   ГОЛОСОВЫЕ ОТПЕЧАТКИ                  │
   │                   делят людей внутри одной плитки      │
   │                        │                               │
   │                        └────────► СШИВКА ◄─────────────┘
   │                              слово → участник
   ▼
txt / md / srt / vtt / json
```

Два независимых прохода: один слышит **что** сказано, другой — **кем**. Сшиваются по
времени: каждое слово достаётся тому участнику, чей интервал речи перекрывает его сильнее.

Подробно: [архитектура](docs/архитектура.md) · [алгоритмы](docs/алгоритмы.md).

## Точность разбивки по участникам

Разметка по видео и разметка по голосу — принципиально разного качества, и это стоит
учитывать при чтении результата.

**По видео — надёжно.** Кто из плиток говорит, определяется практически точно. Ошибки
остаются на быстрых перебиваниях: когда реплики короче секунды, подсветка не успевает
переключиться и обмен репликами склеивается в одну.

**По голосу — приблизительно.** Разделение людей внутри одной плитки держится на
голосовых отпечатках. На записи из общей переговорной проверка даёт около 85%
совпадения на уровне реплики: длинный монолог может разъехаться на двух «участников»,
а похожие голоса — слиться в одного. Это оценка, а не факт.

Что помогает: точное число участников (`--speakers`, ещё лучше `--tile-speakers`),
раздельные микрофоны, длинные реплики.

Что ломает: общая камера и общий микрофон на несколько человек, перебивания и речь
поверх речи, плохая связь и эхо.

Имена участников из видео не читаются: они выдаются как «Говорящий 1..N», сопоставить
с людьми — через `--names`.

**Нумерация идёт не по времени речи.** Номер участника берётся от порядка плиток в кадре,
а внутри плитки — от номера кластера голосов. Сводка в конце прогона отсортирована по
убыванию времени, но номера в ней настоящие: «Говорящий 3» останется третьим, даже если
говорил больше всех. Поэтому надёжный способ подписать участников — прогнать один раз без
`--names`, прочитать сводку и подставить имена по номерам, а точечная форма `"3=Глеб"`
безопаснее позиционной.

## Структура

```
stenogram/
  audio.py         извлечение и загрузка звука (ffmpeg)
  video.py         поиск плиток и подсветки активного говорящего
  models.py        скачивание и кэш ONNX-моделей
  diarization.py   сегментация, голосовые отпечатки, кластеризация
  asr.py           распознавание речи (faster-whisper)
  align.py         сшивка текста с участниками, сборка реплик
  render.py        txt / md / srt / vtt / json
  cli.py           разбор аргументов и оркестрация
service/           REST-сервис: очередь, S3, Docker, клиент transcribe.sh
docs/              техдокументация и план развития
setup.sh           разворачивает окружение
stenogram.sh       запуск из локального venv
```

Модули самостоятельны — пайплайн собирается и из кода:

```python
from pathlib import Path
from stenogram import align, asr, audio, diarization, render, video

src = Path("запись.mp4")
wav = audio.extract_wav(src, Path("/tmp/a.wav"))
segments, lang = asr.transcribe(wav, language="ru")

tiles = video.find_tiles(src)                       # плитки участников
labels, step = video.active_speaker(src, tiles)     # кто подсвечен в каждый момент
vturns = video.to_turns(labels, step, video.word_gaps(segments))

# числа — по плиткам из find_tiles, слева направо: семеро в переговорной, один удалённо
turns, _ = diarization.diarize_with_video(audio.load_wav(wav), vturns, tile_speakers=[7, 1])
render.write(align.assign(segments, turns), Path("запись"), ["txt", "json"])
```

## Зависимости и лицензии

| Компонент | Роль | Лицензия |
|---|---|---|
| faster-whisper + CTranslate2 | распознавание речи | MIT |
| sherpa-onnx + ONNX Runtime | запуск моделей диаризации | Apache 2.0 / MIT |
| pyannote-segmentation-3.0 | границы реплик | MIT (сборка ONNX от k2-fsa) |
| WeSpeaker CAM++ (VoxCeleb) | голосовые отпечатки | Apache 2.0 |
| scikit-learn, numpy | кластеризация и вычисления | BSD |
| ffmpeg | извлечение звука и кадров | LGPL/GPL |

PyTorch не нужен — всё работает на ONNX Runtime и CTranslate2. Это экономит ~2.5 ГБ и
убирает самый капризный шаг установки. Gated-моделей (требующих токен Hugging Face и
принятия условий) в сборке нет.

# Эксплуатация

## Требования

| | |
|---|---|
| Python | 3.10+ (проверено на 3.12) |
| ОЗУ | 4 ГБ свободных при `large-v3-turbo` |
| Диск | ~3 ГБ: окружение 1.1 ГБ, модели 1.6 ГБ, кэш диаризации 36 МБ |
| CPU | любой; на 12 ядрах час записи обрабатывается за ~35 минут |
| GPU | не обязателен; с NVIDIA — в 10–20 раз быстрее |
| ОС | Linux, macOS; на Windows — через WSL |

Права root не нужны: если системного `ffmpeg` нет, статический бинарник ставится в
`./venv` пакетом `static-ffmpeg`.

## Установка

```bash
./setup.sh
```

Скрипт создаёт `./venv`, ставит зависимости, проверяет ffmpeg и скачивает модели
диаризации (~36 МБ). Модель распознавания речи (~1.6 ГБ) скачается при первом запуске.

Переменная `PYTHON` задаёт интерпретатор: `PYTHON=python3.12 ./setup.sh`.

## Полный список параметров

### Основные

| Параметр | По умолчанию | Описание |
|---|---|---|
| `input` | — | видео- или аудиофайл (обязательный) |
| `-o, --output` | рядом с исходником | папка или путь без расширения |
| `-f, --formats` | `txt,md,srt,json` | через запятую: `txt`, `md`, `srt`, `vtt`, `json` |

### Участники

| Параметр | По умолчанию | Описание |
|---|---|---|
| `-s, --speakers` | автооценка | точное общее число участников |
| `--tile-speakers` | — | по плиткам видео, например `"7,1"` |
| `--max-speakers` | 12 | верхняя граница при автооценке |
| `--names` | — | `"Аня,Борис"` или точечно `"3=Глеб"` |
| `--no-diarization` | выкл | только текст, без разбивки |
| `--no-video` | выкл | не использовать подсветку, только голос |
| `--highlight-lag` | 1.2 | на сколько секунд подсветка отстаёт от речи |

### Распознавание

| Параметр | По умолчанию | Описание |
|---|---|---|
| `-m, --model` | `large-v3-turbo` | `tiny`/`base`/`small`/`medium`/`large-v3`/`large-v3-turbo` |
| `-l, --language` | автоопределение | код языка: `ru`, `en`, ... |
| `--prompt` | — | тема, термины, имена собственные |
| `--beam-size` | 5 | ширина луча |
| `--device` | `cpu` | `cpu`, `cuda`, `auto` |
| `--compute-type` | `int8` | `int8` для CPU, `float16` для GPU |
| `--threads` | все минус два | потоки CPU |
| `--denoise` | выкл | шумодав и выравнивание громкости |
| `--keep-wav` | выкл | сохранить извлечённый WAV |

## Работа без интернета

После установки сеть не нужна. Проверяется так:

```bash
env HF_HUB_OFFLINE=1 \
    http_proxy=http://127.0.0.1:1 https_proxy=http://127.0.0.1:1 \
    ./stenogram.sh запись.mp4
```

Прогон должен пройти целиком. Если падает — значит какая-то модель ещё не скачана.

### Подготовка моделей для закрытого контура

`python -m stenogram.models` качает и проверяет обе модели разом — ONNX-разметку с
GitHub Releases и распознавание whisper с HuggingFace, — не заставляя гадать, какая
из двух ещё не докачана:

```bash
# на машине с сетью — разово, перед переносом
./venv/bin/python -m stenogram.models --fetch --whisper large-v3-turbo

# в закрытом контуре — при старте, без единого сетевого запроса
./venv/bin/python -m stenogram.models --check --whisper large-v3-turbo
```

`--check` возвращает 0, если всё на месте, и 1 с текстом вида «нет модели ... в ...»
для каждой недостающей — чтобы сервис падал сразу при старте, а не на первой задаче
через 20 минут. У ONNX-моделей разметки отдельного флага-каталога нет: `--fetch`/
`--check` всегда смотрят в `cache_dir()`, то есть `STENOGRAM_HOME` — так же, как
`diarization.py`, который качает их при первом прогоне. Разойдись это, `--check`
мог бы сказать «всё на месте» про каталог, куда воркер не смотрит; переопределяется
только переменной окружения `STENOGRAM_HOME`, единой для обоих.

`--whisper` принимает и путь к уже готовому каталогу модели, а не только имя
(`tiny`, `large-v3-turbo`, ...) — тогда `--fetch` ничего не качает, только проверяет
`model.bin`/`config.json`/`tokenizer.json`/`vocabulary.*` на месте.

`--whisper-dir` — не то же самое, что `HF_HOME`: это `download_root` библиотеки
faster-whisper (`cache_dir` внутри неё), модели ложатся прямо в указанный каталог,
а не в `<каталог>/hub/...`, куда их кладёт `HF_HOME`. Если задавали `--whisper-dir`
при `--fetch`, тот же путь нужно передать в `asr.load_model(download_root=...)` —
у голого `./stenogram.sh` такого флага нет, он смотрит только на `HF_HOME`. Без
`--whisper-dir` `--fetch`/`--check` работают с тем же кэшем, что и `HF_HOME`.

### Перенос на изолированную машину

Скопировать три вещи:

```
./venv                    окружение с зависимостями и ffmpeg
~/.cache/stenogram        модели диаризации
~/.cache/huggingface      модель распознавания речи
```

Пути переопределяются переменными `STENOGRAM_HOME` и `HF_HOME` — удобно, если модели
лежат на общем разделе:

```bash
export STENOGRAM_HOME=/opt/stenogram/models
export HF_HOME=/opt/stenogram/hf
```

Две особенности переноса, о которых стоит знать заранее.

**Окружение ставится в editable-режиме.** `setup.sh` выполняет `pip install -e .`, и в
`venv` появляется файл-искатель с абсолютным путём до каталога проекта. На другой машине
этот путь не существует, искатель возвращает пустой результат, и импорт уходит на
`PYTHONPATH`, который выставляет `stenogram.sh` — то есть запуск через `./stenogram.sh`
переживает перенос, а голый `python -c "import stenogram"` из скопированного venv может
не найти пакет. Надёжнее переносить репозиторий целиком по тому же пути либо переставить
пакет на новой машине: `./venv/bin/pip install -e . --no-index`.

**Сборка без сети требует setuptools в окружении.** Свежий venv на Python 3.12 содержит
только `pip`: изоляция сборки, которая обычно сама подтягивает `setuptools`, без сети не
работает, и `pip install --no-index .` падает на сборочных зависимостях. Для wheelhouse
кладите `setuptools` версии 77 или новее рядом с остальными пакетами — более старые не
принимают строковую форму `license` из `pyproject.toml`:

```bash
pip download setuptools>=77 -d wheelhouse
pip install --no-index --find-links wheelhouse --no-build-isolation -e .
```

Учтите, что `./venv` содержит абсолютные пути в скриптах: при переносе в другую папку
проще пересоздать окружение через `./setup.sh`, чем править пути.

## Скорость

Ориентир: 12 ядер CPU, `large-v3-turbo`, час записи.

| Этап | Время | Чем определяется |
|---|---:|---|
| Извлечение аудио | ~10 с | скорость диска |
| Поиск плиток | ~40 с | число анализируемых кадров (`samples`) |
| Съём подсветки | ~16 с | декодирование видео, один проход на плитку |
| Распознавание речи | ~25 мин | модель, число потоков |
| Сегментация речи | ~7 мин | длина записи |
| Отпечатки и кластеризация | ~1 мин | число реплик |

Распознавание — узкое место, на него уходит около трёх четвертей времени.

### Как ускорить

- **Видеокарта NVIDIA**: `--device cuda --compute-type float16` — на RTX 3060 час записи
  за 1.6 минуты вместо 33 (замер ниже). Самый большой рычаг, остальные рядом не стоят.
- **Меньше форматов**: на итоговое время влияет слабо, но `json` с потайминговкой по
  словам на длинных записях весит прилично.
- **`--no-video`** экономит около минуты — но ценой качества разметки, обычно невыгодно.

> **Совет «взять `small`» отозван 09.09.2026.** Прежняя редакция обещала пятикратное
> ускорение. Перезамер на одном файле: `small` — 366 с, `large-v3-turbo` — 423 с, то есть
> выигрыш 13%, а не пять раз. Причина расхождения, судя по всему, в том, что пятикратность
> относилась к сравнению с полным `large-v3`, а не с турбо, который стоит умолчанием
> с тех пор: у турбо декодер в 4 слоя вместо 32, и при `beam_size=5` с потайминговкой
> по словам основная работа именно в декодере. Качество при этом расходится сразу —
> `small` дал строчную букву в названии, «главы первые, вторая» вместо «главы 1 и 2»
> и ошибку «достаянием». Менять турбо на `small` ради скорости смысла нет.

### Замер: видеокарта против процессора (09.09.2026)

Сравнение на одном и том же файле: 13 минут русской начитки (LibriVox, общественное
достояние), параметры ровно как в `asr.transcribe` — `beam_size=5`, `word_timestamps`,
`vad_filter`, `condition_on_previous_text=False`.

| Машина | Режим | Распознавание | К реальному | Час записи |
|---|---|---:|---:|---:|
| Ноутбук, i5-13420H, 12 потоков | `cpu/int8`, 10 потоков | 423.3 с | x1.8 | 32.6 мин |
| Системник, RTX 3060 12 ГБ | `cuda/float16` | 20.6 с | x37.7 | 1.6 мин |

**Ускорение в 20 раз.** Карта при этом не загружена целиком: 2528 МБ VRAM из 12 ГБ,
134 Вт из 170, 61 °C. Качество не страдает — `float16` точнее, чем `int8`.

Остальные этапы на том же файле, 5 потоков (столько и берёт CLI):

| Этап | Час записи |
|---|---:|
| Сегментация речи | 5.7 мин |
| Отпечатки | 0.5 мин |
| Чтение WAV | ~0.2 мин |

Материал плотнее типичного заседания: сплошная начитка без пауз, VAD почти ничего не
выбрасывает. Поэтому 32.6 минуты на процессоре — верхняя граница, а не противоречие
таблице выше: та снята на видеоконференции, где паузы есть.

Те же этапы, снятые на настоящем заседании (63.2 минуты, 2 плитки в кадре):

| Этап | На заседании | В пересчёте на час | Где считалось |
|---|---:|---:|---|
| Извлечение аудио | 2.4 с | ~2 с | ноутбук |
| Поиск плиток | 17.9 с | ~17 с | ноутбук |
| Съём подсветки | 30.6 с | ~29 с | ноутбук |
| Распознавание | 94.4 с (**x40.2**) | **1.5 мин** | RTX 3060, float16 |
| Сегментация речи | 289.9 с | 4.6 мин | ноутбук, 5 потоков |
| Границы, разметка, сшивка, запись | 0.4 с | ~0.4 с | ноутбук |

Живая речь с паузами распознаётся быстрее плотной начитки — x40.2 против x37.7, — а
сегментация выходит легче обещанных документацией 7 минут: 4.6 на час записи.

**Следствие для установки на две машины.** С картой распознавание перестаёт быть узким
местом — 1.6 минуты против 5.7 у сегментации. Выносить на отдельную машину имеет смысл
именно распознавание, а сегментацию оставлять там, где больше потоков процессора.
Сегментация зависит только от WAV и не ждёт распознавания, поэтому может идти
параллельно с ним. По сети при этом едет WAV или FLAC (около 1 МБ на минуту записи),
а не исходное видео.

Разбор того, какие ещё этапы можно унести на видеокарту и какой ценой, —
в [ускорении на видеокарте](ускорение-на-gpu.md).

## Разбор проблем

**`ffmpeg не найден`**
Установите системный (`apt install ffmpeg`) либо выполните
`./venv/bin/pip install static-ffmpeg`.

**`Подсветка не найдена — участники только по голосу`**
Детектор не нашёл мерцающих рамок. Причины: сервис не подсвечивает активного говорящего;
запись сделана в режиме одного крупного плана; видео перекодировано с сильным сжатием и
рамка размылась. Разметка продолжится по голосу, но качество будет ниже — задайте
`--speakers`.

**Найдено больше плиток, чем участников**
В кадре есть другие мерцающие элементы. Увеличьте `samples` в `video.find_tiles` или
отключите видео (`--no-video`) и задайте `--speakers`.

**Реплики режутся посередине фразы**
Подсветка отстаёт сильнее обычного. Подберите `--highlight-lag` в диапазоне 0.8–2.0.
Диагностика: доля границ, попавших внутрь слова, — чем меньше, тем лучше.

**Монолог разъезжается на нескольких «участников»**
Голосовые отпечатки шумят. Задайте точное число участников (`--tile-speakers` точнее,
чем `--speakers`). Если люди сидят перед общей камерой, это предел метода — см.
[пределы](алгоритмы.md#пределы-метода).

**Два человека слились в одного**
Похожие голоса. Увеличение числа участников иногда помогает, но чаще разбивает кого-то
третьего. На общем микрофоне надёжного решения нет.

**Модель повторяет одну фразу подряд**
Зацикливание whisper. В проекте оно уже подавлено (`condition_on_previous_text=False`);
если всё же случилось, помогает `--denoise` или другая модель.

**Плохо распознаются фамилии и термины**
`--prompt "Дейли команды разработки. Имена: Аня, Борис, Вика. Термины: деплой, миграция, стейджинг"`.
Подсказка заметно улучшает имена собственные.

**Нехватка памяти**
`large-v3-turbo` в int8 занимает около 2.2 ГБ. Варианты: `--model small`, меньше
`--threads`, либо `--no-diarization` (аудио целиком в память не загружается).

**Медленно на многоядерной машине**
Проверьте `--threads`: по умолчанию берутся все ядра кроме двух. Если параллельно идут
другие задачи, лучше задать явно.

**`Library libcublas.so.12 is not found or cannot be loaded`**
CUDA-библиотеки из пакетов `nvidia-cublas-cu12` и `nvidia-cudnn-cu12` ставятся внутрь
venv, но динамический загрузчик про них не знает. Добавьте их в путь:

```bash
V=./venv/lib/python3.12/site-packages/nvidia
export LD_LIBRARY_PATH="$V/cublas/lib:$V/cudnn/lib:$LD_LIBRARY_PATH"
```

Коварство в том, что проверка `ctranslate2.get_cuda_device_count()` при этом отвечает
`1` и список типов включает `float16`: она дёргает только драйвер. Отказ приходит позже,
на первом настоящем вызове энкодера — то есть уже после загрузки модели в видеопамять.
Системная установка CUDA toolkit при этом не нужна.

**Модель с Hugging Face качается неприемлемо медленно**
Замечено 09.09.2026 на канале, где обычная скорость 1.5 МБ/с: HF отдавал около 8 КБ/с,
это больше суток на 1.6 ГБ. Кэш моделей переносим — скопируйте его с машины, где модель
уже скачана, вместо повторной загрузки:

```bash
rsync -a --partial --info=progress2 \
      ~/.cache/huggingface/hub/models--mobiuslabsgmbh--faster-whisper-large-v3-turbo \
      машина:~/.cache/huggingface/hub/
```

Версии `faster-whisper` на обеих машинах должны совпадать: имя репозитория для
`large-v3-turbo` задано в `faster_whisper.utils._MODELS` и от версии зависит.

## Проверка после изменений в коде

Быстрая проверка на коротком фрагменте:

```bash
./venv/bin/python -c "
from pathlib import Path
import subprocess, sys
sys.path.insert(0, '.')
from stenogram.audio import find_ffmpeg
ff, _ = find_ffmpeg()
subprocess.run([ff, '-y', '-v', 'error', '-ss', '600', '-t', '60',
                '-i', 'запись.mp4', '-c', 'copy', '/tmp/clip.mp4'])
"
./stenogram.sh /tmp/clip.mp4 -m small -l ru -f txt -o /tmp/проверка
```

Минута записи с моделью `small` проходит весь пайплайн примерно за минуту — этого хватает,
чтобы поймать поломку в любом из шагов.

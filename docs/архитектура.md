# Архитектура

## Принцип

Пайплайн собран вокруг одной мысли: **что** сказано и **кем** сказано — это две разные
задачи с разными источниками сигнала, и решать их надо порознь, а сшивать в конце по
времени.

Из этого следует всё остальное:

- распознавание речи ничего не знает об участниках и не пытается угадывать смену
  говорящего;
- разметка участников ничего не знает о тексте и работает с сигналом — картинкой и
  голосом;
- единственная точка стыковки — временная шкала, общая для обоих проходов.

Такое разделение позволяет менять любой из проходов независимо: подставить другую модель
распознавания, добавить новый источник сигнала о говорящем, переписать кластеризацию —
остальное не заметит.

## Поток данных

```
                          вход: медиафайл
                                 │
              ┌──────────────────┴──────────────────┐
              │                                     │
        audio.extract_wav                     video.find_tiles
        WAV 16 кГц моно                       список Tile
              │                                     │
              │                            video.active_speaker
              │                            метки плиток, 5 раз/с
              │                                     │
        asr.transcribe                              │
        list[Segment] c list[Word]                  │
              │                                     │
              ├────► video.word_gaps ──────────────►│
              │      паузы между словами     video.to_turns
              │                              сдвиг на lag + привязка к паузам
              │                                     │
              │                                 list[Turn]
              │                                     │
              │                          diarization.diarize_with_video
              │                          деление плиток на людей по голосу
              │                                     │
              │                                 list[Turn]
              │                                     │
              └──────────────► align.assign ◄───────┘
                               слово → участник
                                     │
                              list[Utterance]
                                     │
                               render.write
                                     │
                       txt / md / srt / vtt / json
```

Порядок неслучаен: **распознавание идёт до разметки участников**, потому что паузы между
словами нужны, чтобы поставить границы реплик по видео в правильные места. Без этого
подсветка режет фразы посередине.

## Модули

| Модуль | Отвечает за | Зависит от |
|---|---|---|
| `audio.py` | поиск ffmpeg, извлечение WAV, загрузка в numpy | — |
| `video.py` | поиск плиток, подсветка активного говорящего, границы реплик | `audio` (ffmpeg) |
| `models.py` | скачивание и кэш ONNX-моделей | — |
| `diarization.py` | сегментация, отпечатки, кластеризация, сглаживание | `audio`, `models` |
| `asr.py` | распознавание речи с потайминговкой по словам | — |
| `align.py` | сшивка слов с участниками, сборка реплик, статистика | `asr`, `diarization` |
| `render.py` | форматы выгрузки | `align` |
| `cli.py` | разбор аргументов, оркестрация, вывод прогресса | все |

Зависимости направлены в одну сторону, циклов нет. `asr.py` не зависит ни от чего внутри
проекта — его можно вынести целиком. `video.py` тоже почти автономен: ему нужен только
`find_ffmpeg` из `audio.py`.

Тяжёлые библиотеки импортируются внутри функций, а не на уровне модуля: `faster_whisper`
в `asr.transcribe`, `sherpa_onnx` в `diarization.segment` и `diarization.embed`,
`sklearn` в `diarization.cluster`. Поэтому `import stenogram` стоит миллисекунды, и
`--help` не ждёт загрузки ONNX Runtime.

## Структуры данных

Четыре простых dataclass, по одному на каждый этап. Все времена — в секундах от начала
записи, float.

```python
@dataclass
class Word:          # asr.py — слово с потайминговкой
    start: float
    end: float
    text: str        # с ведущим пробелом, как отдаёт whisper

@dataclass
class Segment:       # asr.py — кусок распознавания
    start: float
    end: float
    text: str
    words: list[Word]

@dataclass
class Turn:          # diarization.py — интервал речи одного участника
    start: float
    end: float
    speaker: int     # индекс с нуля
    # .duration -> float

@dataclass
class Utterance:     # align.py — итоговая реплика стенограммы
    start: float
    end: float
    speaker: int
    text: str
    words: list[Word]
```

`Turn` — общая валюта разметки участников. Его отдают и `video.to_turns`, и
`diarization.diarize`, и `diarization.diarize_with_video`; `align.assign` принимает любой
источник и не знает, откуда взялись метки. Именно поэтому новый источник сигнала о
говорящем встраивается без правки остального кода.

## Оркестрация

`cli.main` выполняет четыре шага и печатает прогресс:

1. **Извлечение аудио.** WAV 16 кГц моно во временную папку (или рядом с результатом
   при `--keep-wav`). При `--denoise` добавляется цепочка фильтров
   `highpass → afftdn → dynaudnorm`.
2. **Поиск плиток.** Только если во входе есть видеодорожка и не указан `--no-video`.
   Ошибки на этом шаге не фатальны: не нашлось плиток — пайплайн честно сообщает и
   переходит на разметку по голосу.
3. **Распознавание речи.**
4. **Разметка участников.** Гибридная, если плитки найдены, иначе только по голосу.

Дальше — сшивка, подстановка имён и запись форматов.

Аудиофайл в память загружается один раз (`audio.load_wav`) и освобождается сразу после
разметки: час записи в float32 — это 242 МБ, и держать его во время рендеринга незачем.

## Расширение

**Другой источник сигнала о говорящем.** Отдайте `list[Turn]` — и всё. Например, лог
конференции с временами включения микрофонов ложится в ту же схему.

**Другая модель распознавания.** Замените `asr.transcribe`, сохранив контракт: вернуть
`list[Segment]` со заполненным `words` и код языка. Потайминговка по словам обязательна —
на ней держится и привязка границ, и сшивка.

**Другая модель отпечатков.** Правьте `models.EMBEDDING_URL` и `EMBEDDING_FILE`.
Требования: ONNX, вход 16 кГц моно, любая размерность на выходе — эмбеддинги нормируются
внутри. Учтите, что модель сильно влияет на качество: см. [замеры](алгоритмы.md).

**Новый формат выгрузки.** Добавьте функцию в словарь `render.WRITERS` — CLI подхватит
её автоматически, включая проверку значения `--formats` и подсказку в `--help`.

## Кэш и файлы на диске

| Путь | Что | Размер |
|---|---|---|
| `./venv` | окружение с зависимостями и ffmpeg | ~1.1 ГБ |
| `~/.cache/stenogram` | ONNX-модели сегментации и отпечатков | ~36 МБ |
| `~/.cache/huggingface` | модель распознавания речи | ~1.6 ГБ |

Путь к моделям диаризации переопределяется переменной `STENOGRAM_HOME`, к модели
распознавания — стандартной `HF_HOME`. Обе папки переносимы: скопируйте на машину без
интернета, и всё заработает.
